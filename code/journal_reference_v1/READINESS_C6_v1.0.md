# Bounded C6 readiness integration v1.0

`analysis_admission.py` is a read-only admission/selection/export boundary over
unchanged PAP metric callables. `batch_accounting.py` is an external sequential
operator reservation/reconciliation workflow. Neither has run/dispatch,
permission-signing or permission-generation actions. Scientific contracts,
primary Q/4, native guards, old C5 schemas and historical policies are unchanged.

## Analysis trust and native binding

An admission file is supplied with its independently trusted **raw SHA256**;
self-reported PASS is not authority. The pinned admission binds canonical PAP
bytes, analysis and validator commit/tree/full inventory, actual runtime,
original config text/effective hashes, exact expected groups/contrasts, native
file inventories, selected whole-group attempt and separately authorized repair
lineage. Sources are external immutable directories. The reviewed validator is
exact deea6aa7; this version supplies no general historical compatibility. It
cannot read initial01 by pretending its generation is deea. The existing exact
initial01 policy is untouched and is not exercised by this delta.

Each source is replayed through its unchanged native validator in a clean,
separate deea checkout with the pinned interpreter/runtime. Production uses
`verify_accounting(..., identity_requirement='required')`, including partial
parents and native cause/stage verification. Only a complete selected queue
admits scientific rows. Unverified/invalid source/content rejects. All input
bytes and source anchors are checked again before export. Prior native runtime
identity must actually match the admitted validation runtime; there is no bypass.

Conformance sources are available only to explicitly `SYNTHETIC_TEST_ONLY`
admissions and structural fixtures T<=8. That route runs actual strict native
validation; synthetic fixture authorities/receipts cannot admit production.
The test fixture derives one saved C/C PD control cell, literal actions/payoffs,
and its private decide/update readback for six descriptors. It calls no
Engine.step/run and no external game evaluator; it is not a measured episode.
Synthetic repair authority exists only in test admission objects, not grants.

A selected candidate contains every registered member: hybrid full + five
switches, plus two kinds for base groups. No leaf from another group attempt can
be inserted. Repair requires new IDs, exact replay_of, explicit separate pinned
whole-group repair authority; production additionally verifies failed transient
parent and actual native recovery ancestry. Originals stay read-only. Missing
or invalid content cannot produce a COMPLETE envelope; missing native source or
strict binding rejects before output. Existing completeness primitives keep all
registered N and full-dependent propagation; no successful-subset denominator.

The new schema `ANALYSIS_C6_v1.0.json` has closed admission and C6 envelope
alternatives; it does not relabel C6 as C5. Metrics/cells retain the accepted
callable payloads. Structural schema checking alone is insufficient: `verify`
repeats native checks and recomputes the entire envelope byte-for-byte under
canonical JSON, rejecting changed schema/bindings/metrics. Export is exclusive
and outside native directories. No normalized alternative is adopted: Q/rank/
discordance/persistence are null, PAP_OWNER_DISPOSITION_REQUIRED.

```
python -m journal_reference_v1.analysis_admission export --admission ADMISSION \
 --admission-sha256 TRUSTED_RAW_SHA --protocol PAP --validator-source CLEAN_DEEA \
 --python PINNED_PYTHON --output NEW_EXTERNAL_JSON
```

`verify` uses the same arguments and existing output. Exit0 means complete in the
explicit kind; exit2 means failure/incomplete. This analysis boundary does not
reinterpret native exit3 as accepted identity. Generation/validation/analysis
identities are separate fields. No artifact or analysis PASS grants execution.

## External sequential operations

Allocation proposals bind exact per-batch native plan/allowlist, ordered IDs,
whole condition groups, output identity and disjoint reservation intervals for
attempts, charged-started T, final-sealed queue wall and raw native output bytes.
RSS/episode are maxima; CPU sample, archive, staging and validation costs remain
separate domains. Each initial allocation has zero replay. Sum all allocations
for an explicit aggregate proposal; never infer global caps from partition count.

`audit` reconstructs sequence from a hash-chained append-only event stream and an
**independently retained expected tip**. Files are created exclusively with fsync;
this is a sequential operator workflow, not a concurrent scheduler, lock service
or anti-rollback authority. Rollback/fork detection depends on the external tip.
There is no dispatch command. Reserve one exact batch; the next remains blocked
until actual native validation, lossless archive and readback checkpoints. Any
failed, unknown, unresolved or late-failure state halts. Reservations are retained
at full caps, never recycled to cover favorable observed consumption. Resource
overshoot is recorded, not truncated. Actual charged consumption remains separate
from planned reservation and committed rounds/known-unstarted tail.

`reconcile_native` computes an initial-batch production receipt from real strict
native accounting and a byte-exact/CRC archive readback, including final seal
bytes. It never accepts a caller-authored PASS as a production checkpoint. Its
receipt then joins the externally pinned operator ledger. Pure `audit` verifies
receipt consistency, not physical truth; a trusted tip pins the actual reconciler
receipt. A synthetic receipt cannot join a NATIVE_VERIFIED proposal. Operators
must retain failed originals/raw/archive/checkpoints and stop on reconciliation
errors; a missing receipt leaves the reservation outstanding.

Successful-parent recovery is forbidden as continuation. Synthetic controls prove
that only a separate whole-group repair allocation with fresh IDs/replay_of and
an explicit failed transient parent can resolve the halt. **Initial production
proposal has zero repair allocation. Native cumulative repair reconciliation is
intentionally not admitted here**: a separate reviewed parent-cap/replay
allocation and permission are required, and this function fails closed for it.
This is a future explicit-repair boundary, not permission to retry a batch.
No production repair action is required or authorized for initial readiness.

## Reuse / admission limits

The 537 parent paths, including accepted pure metrics, model, validator, native
schemas, runtime qualification, CPU and scientific/config dependencies remain
byte-identical. Prior independent PASS is reused in its declared domain. New
bindings require targeted delta review. Candidate worker, paths/storage, exact
future runtime, adoption of caps/retention and alternative divisor disposition
remain external prerequisites. Preparation is not full R1, U2 or freeze.
