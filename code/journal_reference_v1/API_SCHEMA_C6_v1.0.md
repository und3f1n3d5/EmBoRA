# API and complete serialization contract — C6 P2 v1.0

`prepare_config(source)` resolves only frozen YAML defaults, then `validate_config` checks the closed effective object. `State.from_primary/from_dict` reject invalid numeric domains, bool/string coercions, missing K keys and inconsistent derived IEEE values. Explicit K folds implement F06/F09/F25; F35 alone uses math.fsum.

`Agent.construct(config,id,Adapter(selection,purpose))` binds one immutable selection. `Agent.decide({public_observation,own_pre_state})` is pure. `validate_decision` independently recomputes the typed trace through the same policy path before execution. `candidate_choice` uses both raw current-action targets and the common native `channel_projection`; no candidate state commits. `prepare_update` takes the saved pre-state, observation, validated decision, immutable Result and expected round; it returns a post-state and update trace without mutation. Engine alone commits both states/history/log and one counter increment per seat. Stateless baseline state/readouts remain JSON null.

Native scientific action computation is in numeric.py/formulas.py/model.py. The hash-pinned independent exact-rational reference is called only by audit diagnostics/runtime qualification, never as fallback, expected-output copying or a second action policy. Failure of arithmetic/input/total bounds invalidates diagnostics even when O−B would pass. Unknown-origin actual ideal/input/total fields are absent. Known explicit original decimal/rational tokens must round to the supplied input bits; signed zero token signs are retained. Initial/effective source components and derived quantities are serialized independently.

Machine inventories in `schemas/` enumerate every field/shape of source/effective configs, manifest, private round and numeric evidence. They reject unknown object keys and encode scalar/array/nullable alternatives; closed Python validators additionally enforce cross-field identities, contexts, game/history legality, exact rounded operands/zero signs, adapter agreement, graph nodes and recomputed N/P/D/category. JSON Schema alone is insufficient for these mathematical relationships. SHA256 of each inventory is part of the P2 schema manifest and source inventory.

Manifest: original/effective config and hashes, original text/tokens or explicit unknown-token provenance, source/effective initial states, full constants/enums, adopted IDs/input hashes, runtime/FP/dependency lock, commit/branch/dirty/source hashes, DGP/pairing/no-RNG declaration, authority, failure state and diagnostic trajectory hash. The runtime hash is SHA256 of canonical JSON; the pretty file has its own byte SHA256.

Round: complete observations, both pre-states, iota/theta/aE/aR/branch/action, four candidate target/projection/evidence channels with N/P/D/category, both public results, selected-adapter realized raw q and applied q_star, Delta/urgency/V/L/focus/rho, sigma and raw/applied cost, preclip mood/fatigue, unprojected/committed post-state, intervention identity, normative event order and counters, failure status. Candidate and realized fields are distinct. F32 copies nonmaterial pre-v bits before the same recurrence helper; it never deletes candidate votes.

Artifact files are exactly manifest.json, rounds.json, failures.json and artifact_hashes.json. The last file hashes the first three (no self-hash claim). Review/recovery manifests separately hash complete artifacts. Duplicate keys, nonfinite values, scalar critical mismatches and malformed/tampered logs fail. Decisions and updates use exact structural/bit comparisons; continuous O−B numerical acceptance and scientific numerical residuals have distinct roles.

Scope: bounded owner conformance establishes covered code/spec correspondence on the qualified runtime. It does not establish universal correctness, human construct validity, empirical frequencies, article claims, independent audit, code freeze or permission to run a pilot/full experiment.
